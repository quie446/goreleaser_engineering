# tool — multi-arch release engineering demo

A minimal zero-dependency Go module released with GoReleaser. Lives under
`tool/` so it does not touch the surrounding repository's module.

Matrix: `linux`/`darwin` × `amd64`/`arm64` → 4 tar.gz archives, one
`checksums.txt` over the archives, and one CycloneDX 1.6 SBOM per archive
(generated by `syft`).

## Prerequisites

- Go 1.22+
- `make`, `curl`, `tar`

`goreleaser` (v2.12.0) and `syft` (v1.42.4) are downloaded into `tool/bin/`
automatically by `make tools`; nothing is installed globally.

## Commands

```sh
cd tool
make test               # unit tests
make release-check      # goreleaser check + negative test (a bad config must fail)
make release-snapshot   # -> dist/ with archives, checksums.txt, *.sbom.cdx.json
make release-verify     # two snapshot builds; diffs checksums.txt; fails if they differ
```

Every command exits non-zero on failure.

## Version injection

- Release/tag builds: GoReleaser sets
  `-X main.version={{ .Version }} -X main.commit={{ .ShortCommit }}` from the
  Git tag and commit.
- Snapshot builds: version is `v<next-patch>-dev.<short-commit>` and is
  deterministic for a given commit — no wall-clock component.
- Plain `go build` without ldflags still reports a commit via the
  `vcs.revision` setting embedded by Go itself (`debug.ReadBuildInfo`).

Check:

```sh
tar -xzf dist/tool_*_linux_arm64.tar.gz -C /tmp
/tmp/tool --version
# version=0.0.0-dev.1a2b3c4 commit=1a2b3c4
```

## Reproducibility

Archive member mtimes and gzip header timestamps are pinned to the commit
timestamp (`metadata.mod_timestamp`), and binaries are built with
`CGO_ENABLED=0 -trimpath`, so two builds of the same commit produce
byte-identical archives and identical `checksums.txt` lines.

```sh
make release-verify
# or manually:
goreleaser release --snapshot --clean && cp dist/checksums.txt /tmp/c1.txt
goreleaser release --snapshot --clean && cp dist/checksums.txt /tmp/c2.txt
diff -u /tmp/c1.txt /tmp/c2.txt   # must be empty
```

Documented exception: the `*.sbom.cdx.json` files are deliberately excluded
from `checksums.txt` (`checksum.ids: [default]`) because CycloneDX documents
carry a generation timestamp (`metadata.timestamp`) and generator metadata,
so their bytes change between builds even when the archived binaries do not.
The archives themselves — the thing `checksums.txt` certifies — are
byte-stable.

## CI

`.github/workflows/tool-release.yml`:

- Pull requests touching `tool/`: `make test` + `make release-check`.
  A broken `.goreleaser.yaml` (or a validator that stops rejecting broken
  configs) fails red.
- Tags `tool-v*`: `goreleaser release --snapshot --clean` on a full
  checkout, a `--version` smoke test, and artifacts uploaded to the workflow
  run. No tokens or external services are required.

No secrets are stored in the repository. The snapshot job never publishes a
GitHub Release.

## Real release (requires a token)

Required environment:

- `GITHUB_TOKEN` (or `GH_TOKEN`) with `contents: write` — used by GoReleaser
  to create the Release and upload assets. Never commit it.

```sh
git tag tool-v1.0.0
git push origin tool-v1.0.0
GITHUB_TOKEN=$TOKEN ./bin/goreleaser release --clean   # from tool/
```

To switch the tag job from snapshot to a real publish, replace
`goreleaser release --snapshot --clean` with `goreleaser release --clean`
and grant the workflow job `permissions: contents: write`.
